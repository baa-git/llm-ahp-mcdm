# llm-ahp-mcdm

From a raw data set to a ranking with the Analytic Hierarchy Process (AHP), with large language models as the
respondents of the pairwise comparisons. The `ahp_bench` package and the `ahp-bench` command profile a CSV,
turn columns into criteria and an AHP hierarchy, compute the alternatives x indicators performance matrix,
ask LLM respondents the pairwise-comparison questions, compute eigenvector weights and consistency ratios
(CR), optionally revise inconsistent answers, and rank the alternatives with TOPSIS, ARAS and EDAS. An agent
skill lets Claude Code, Codex or another coding agent run the whole workflow and show each step.

| Stage | Step | Commands |
| --- | --- | --- |
| 0 | EDA of the data set | `eda` |
| 1 | criteria and AHP hierarchy (written, templated or proposed by an LLM) | `criteria template / validate / propose`, `host criteria-prompt / criteria-ingest`, `hierarchy` |
| 2 | performance matrix and problem file | `criteria build` |
| 3 | pairwise comparisons and AHP weights | `host prompts / ingest` (subscription) or `run` (OpenRouter) |
| 4 | consistency check and revision | `report`, `host revise-prompts / revise-ingest` or `revise` |
| 5 | ranking (TOPSIS, ARAS, EDAS) | `report`, or `rank` with weights you already have |
| 6 | report and audit | `report`, `audit` |

Two ways to get answers (stages 1 and 3):

- **Subscription (host) mode - no API key.** Your Claude Code or Codex session gives each prompt file to an
  independent subagent; the package parses the replies. One underlying model; temperature and reasoning cannot
  be set; panelists are repetitions of that model, not different models.
- **API mode - OpenRouter.** A panel of models is called with your own key, a dry run and a budget cap. Every
  call is logged with the parameters requested and applied, tokens and cost.

Everything is logged as JSON lines and every number in a report is recomputed from those logs; an offline
audit checks prompts, parsing and arithmetic. The published nine-model study is in
[llm-ahp-mcdm-study](https://github.com/baa-git/llm-ahp-mcdm-study).

## Install

```
pip install git+https://github.com/baa-git/llm-ahp-mcdm@v1.0.0                                  # Python 3.10+, numpy
pip install "llm-ahp-mcdm[figures] @ git+https://github.com/baa-git/llm-ahp-mcdm@v1.0.0"        # with matplotlib
```

Or clone the repository and run `python -m ahp_bench <command>` from its root. Stages 0-2 use the standard
library only; matplotlib is optional (hierarchy figure, study figures). Everything except API mode is offline.

## Quick start: synthetic data set to ranking (no key, no cost)

`examples/orders_synthetic.csv` holds 400 **invented** supplier orders (generated by
`examples/make_orders_synthetic.py`, seeded) and `examples/orders_spec.json` a criteria spec for them.

```
ahp-bench example --out demo && cd demo
ahp-bench eda --data orders_synthetic.csv --out eda                                   # eda/eda.md, eda/eda.json
ahp-bench criteria validate --spec orders_spec.json --data orders_synthetic.csv       # tree + matrix
ahp-bench criteria build --spec orders_spec.json --data orders_synthetic.csv \
    --out problems/orders.json --confirmed                                            # problem file + provenance
ahp-bench hierarchy --problem problems/orders.json --out hierarchy                    # hierarchy.md (Mermaid), .png
ahp-bench host prompts --problem problems/orders.json --conditions direct --panelists 3 --out work
```

Each file in `work/prompts/` goes to one fresh subagent, whose JSON reply is saved as
`work/replies/<same name>.json`. Then:

```
ahp-bench host ingest --problem problems/orders.json --dir work --results results/orders --tag main --model-name <host model>
ahp-bench report --problem problems/orders.json --results results/orders                # report/report.md
ahp-bench audit  --problem problems/orders.json --results results/orders
```

API mode instead of the subagents: `ahp-bench run --problem problems/orders.json --conditions direct --reps 3
--budget 1 --tag main --dry-run --print-prompts`, then the same command without `--dry-run`.

## Using the skill from Claude Code and Codex

`skills/llm-ahp-mcdm/` is an Agent Skill (`SKILL.md` with `name`/`description` frontmatter plus
`references/`). It starts with the five-minute walk-through on the synthetic example, then runs the stages
above, shows the EDA, the criteria, the hierarchy and the matrix, asks you to confirm them before any
weighting, runs subscription or API mode (asking for an explicit budget before any paid step), and finishes
with the report and the audit. It never asks you to paste a key and never invents criteria values or weights.

| Route | Command |
| --- | --- |
| Claude Code, all projects | `ahp-bench install-skill --claude` (copies to `~/.claude/skills/llm-ahp-mcdm/`) |
| Codex | `ahp-bench install-skill --codex` (copies to `~/.codex/skills/llm-ahp-mcdm/`) |
| One project | `ahp-bench install-skill --project` (`./.claude/skills/llm-ahp-mcdm/` plus a pointer in `./AGENTS.md`) |
| Any other skills folder | `ahp-bench install-skill <DIR>` |
| Claude Code plugin | `/plugin marketplace add baa-git/llm-ahp-mcdm`, then install the `llm-ahp-mcdm` plugin (`.claude-plugin/`) |
| Generic skill installers | standard layout, e.g. `npx skills add baa-git/llm-ahp-mcdm` |
| Agents reading `AGENTS.md` | start the agent in a clone; `AGENTS.md` points to the skill |

Skill locations and plugin commands can change between tool versions; check your tool's documentation.
Then ask, for example: "Use the llm-ahp-mcdm skill to rank the suppliers in orders.csv."

## Conditions (prompt variants)

Technique (zero-shot or chain-of-thought) and guidance are independent.

| Guidance | Zero-shot | CoT | Prompt content |
| --- | --- | --- | --- |
| unguided (default) | `direct` (stored `lean`) | `cot` | criterion names only |
| described | `described` | `described-cot` | names plus neutral criterion descriptions |
| guided | `guided` (stored `user_guided`) | `guided-cot` (`user_guided_cot`) | descriptions plus the user's own priority order and hints |
| study only | `guided` (verbatim thesis prompts) | - | priority order, importance hints, data report |

`described` and `guided` need `descriptions` (and `guidance`) blocks in the problem file, managed with
`ahp-bench guidance` (drafts by code, by a subagent or by an API model; importance cues are refused for
`described` unless `--allow-cues`). The guided priority order must come from the user's own stated
priorities; a draft or unconfirmed block prints a warning that the report repeats. Weights obtained under
guidance largely reproduce the guidance; run an unguided condition alongside (`--conditions direct,guided`).
Records, prompt ids and hashes of the study are unchanged.

## Command reference

| Command | Purpose |
| --- | --- |
| `ahp-bench example --out DIR` | copy the synthetic example (CSV, criteria spec, generator) |
| `ahp-bench eda --data FILE [--alternative-column COL] --out DIR` | stage 0: `eda.md`, `eda.json` (types, missing values, summaries, candidate alternatives and indicators) |
| `ahp-bench criteria template --eda DIR/eda.json --out SPEC` | draft criteria spec from the EDA suggestions (to review) |
| `ahp-bench criteria validate --spec SPEC --data FILE` | check a spec against the data; print tree and matrix |
| `ahp-bench criteria build --spec SPEC --data FILE --out P [--confirmed]` | performance matrix and problem file with provenance |
| `ahp-bench criteria propose --eda E --data FILE --out SPEC --model M --budget USD [--dry-run]` | API mode: criteria proposal by one model |
| `ahp-bench host criteria-prompt / criteria-ingest` | subscription mode: criteria proposal by a subagent |
| `ahp-bench hierarchy --problem P [--out DIR]` | text tree; `hierarchy.md` (Mermaid, indicator table); `hierarchy.png` |
| `ahp-bench guidance draft-descriptions / descriptions-prompt / descriptions-ingest / descriptions-propose / set-order / confirm / check` | neutral descriptions, user priorities, confirmations |
| `ahp-bench new-problem --out FILE` | commented problem template (criteria without data) |
| `ahp-bench problem FILE` | validate a problem file and print a summary |
| `ahp-bench host prompts / ingest / revise-prompts / revise-ingest` | subscription mode: prompt files, reply ingestion, revision loop |
| `ahp-bench run --problem P --conditions direct,cot --reps N --budget USD [--dry-run]` | API mode, first answers |
| `ahp-bench revise --problem P --source-tag main --tag revision [--judge] --budget USD [--dry-run]` | API mode, revision of matrices with CR > 0.10 |
| `ahp-bench report --problem P --results DIR [--experts FILE] [--revision-tag T] [--latex]` | hierarchy, tables (CSV), `report.md` |
| `ahp-bench rank --problem P --weights W.json [--out DIR]` | rankings with weights you already have |
| `ahp-bench audit --problem P --results DIR` | read-only checks of the records |
| `ahp-bench reparse --problem P --results DIR` | re-parse stored replies with the current parser |
| `ahp-bench tech-report --results STUDY/results --data STUDY/data` | Turkish technical report of the published study |
| `ahp-bench install-skill --claude / --codex / --project / DIR` | install the agent skill |

New problems write to `results/<problem name>/` unless `--results DIR` is given; records of different
problems are never mixed in one file. Expert matrices (`--experts FILE`):
`{"experts": [labels], "<task>": [one n x n matrix per expert], ...}`.

### Criteria spec (stages 1-2)

JSON with `proposed_by` (`human` | `host agent` | model id), `problem` (name, title, goal, role),
`alternative_column`, optional `alternatives` and `filter`, `indicators` (id, label, aggregation, source
column(s), optional filter, direction, unit, rationale, scale, offset) and `hierarchy` (3-9 main criteria,
optional 3-9 sub-criteria each, each leaf mapped to exactly one indicator). Aggregations: `mean`, `sum`,
`median`, `min`, `max`, `count`, `share` (column == value), `ratio` (sum / sum), `mean_days_between`.
Details: `skills/llm-ahp-mcdm/references/data-workflow.md`.

### Problem file

| Key | Meaning |
| --- | --- |
| `name`, `title` | identifier (lower-case, default results folder) and display title |
| `goal` | neutral noun phrase used in the prompt: "N criteria used in *goal* are compared in pairs" |
| `role` | first line of the system message (a respondent, never a preferred answer) |
| `criteria`, `short` | 3-9 main criteria; optional short labels for tables |
| `groups` | optional sub-criteria groups: `task` name, `parent` main criterion, 3-9 `criteria` |
| `question_order` | optional per task, 1-based `[left, right]` pairs; default (1,2), (1,3), ..., (n-1,n) |
| `ranking` | optional: `alternatives`, `indicators` (code, name, unit, direction; from a data set also source, aggregation, filter, rationale), `criterion_indicator`, `matrix` (> 0), optional `transform` (`row_share_percent`) |
| `provenance` | written by `criteria build`: data file name and sha256, rows, spec hash, `criteria_proposed_by`, `criteria_confirmed_by_user`, data summary |
| `descriptions` | optional: neutral text per criterion, `drafted_by`, `confirmed_by_user` (described level) |
| `guidance` | optional: `source` (`user` / `orchestrator-draft`), `confirmed_by_user`, `user_statement`, `order` and `hints` per task (guided level) |

## Verifying the published study

The study's records, data and reports are in
[llm-ahp-mcdm-study](https://github.com/baa-git/llm-ahp-mcdm-study); this repository contains the problem
definition and guided prompt files the commands need (`problems/`). No API calls are made:

```
git clone https://github.com/baa-git/llm-ahp-mcdm-study ../llm-ahp-mcdm-study
python -m unittest discover -s tests
ahp-bench audit  --results ../llm-ahp-mcdm-study/results --out ../check
ahp-bench report --results ../llm-ahp-mcdm-study/results --data ../llm-ahp-mcdm-study/data \
    --tag main --revision-tag revision_final --out ../check
diff -r ../check/tables ../llm-ahp-mcdm-study/results/report/tables
```

The audit runs 86 expectation checks, all passing; the regenerated tables are byte-identical to the
published ones. Setting `AHP_STUDY_DIR` to the study folder also enables the unit tests that compare with the
published records.

## Configuration

- `models.json` (default `--models-file`) is the study's panel: nine models, temperature 0.6, max tokens 8000,
  reasoning `effort=none` (gpt-4o: parameter omitted; minimax-m2.5: `effort=minimal`) and the judge
  `x-ai/grok-4.20` at temperature 0. Copy and edit it for another panel; `criteria propose` and
  `guidance descriptions-propose` take a key of this file or any OpenRouter model id.
- Keys (API mode only): `OPENROUTER_API_KEY` or the per-model variables named in `models.json`, from the
  environment or a git-ignored `.env` in the working folder (see `.env.example`). Keys are scrubbed from every
  record. Unsupported `reasoning` values are stepped down `none -> minimal -> low -> omitted` and an unsupported
  temperature is omitted; what was applied is stored per record.

## Costs

Subscription mode uses your agent subscription and records no cost. In API mode `--dry-run` prints an estimate
from the study's billed cost per question (`ahp_bench/cost_reference.json`; unknown for other models and for
criteria or description prompts), and `--budget` caps spending per run tag, checked before every call. The
published study cost 4.27 USD in total.

## Limitations

- LLM answers are not expert judgement; weights describe the models, prompts and dates used. Agreement with
  expert weights is a similarity measure, not a quality measure.
- EDA suggestions are heuristics: directions are suggested from column names only, and criteria proposed by
  an LLM need a person's review. Hierarchies have at most two levels and one indicator per leaf.
- Subscription mode: one model, no control of temperature or reasoning, no token or cost records; panelists are
  repetitions, not different models.
- API mode: model versions behind an OpenRouter id, provider routing and prices can change; some models ignore
  temperature or cannot disable reasoning (see `skills/llm-ahp-mcdm/references/pitfalls.md`).
- Revision changes priorities; revised weights are a different measurement, not a correction. Guided weights
  restate the guidance.
- The figures, appendix and Turkish technical report are specific to the published study.
